# 沉浸式互動教學網站與 GitHub Pages

依使用者要求完成實作、測試及必要的發布；一般以繁體中文與臺灣教育用語溝通。使用者的明確要求、所在環境規則與既有專案約束優先。可單獨執行製作、改版或部署；沒要求發布時先完成可預覽成果。

## 1. 釐清教學與素材

- 從現有對話、專案和使用者提供的素材取得主題、年級、學習目標、場景、可用圖片與音樂、預計設備及公開範圍。關鍵資訊缺漏且會改變成果時簡短詢問，其餘採合理預設並繼續。
- 將目標映射成數個有意義的可操作任務；例如情緒溫度計、排序、句子拼組、呼吸練習、訊息分類。提供操作說明、適齡回饋、完成條件及可再次嘗試的方式。避免只做選擇題；提供點擊替代拖曳以支援觸控與鍵盤。
- 若需要生成場景圖片或圖片提示詞，讀取 [references/image-prompts.md](references/image-prompts.md)，提供每個場景可直接貼到 Gemini 或 ChatGPT 的完整提示詞；分開給真正球形全景與一般場景圖的方案，並據實驗證。
- 尊重素材的使用與公開授權；不擅自把學生姓名、照片或敏感資料公開。若須取得或製作新素材，使用目前環境可用工具，明確區分示意圖與真實素材。
- 辨認圖片是否為真正的 2:1 等距長方投影 360 度全景。普通圖片不可宣稱具有完整 360 度視野；可設計平面拖曳視窗或有限角度場景並清楚標示。只有確實支援才稱為真實 3D 或球形全景；避免暈眩並提供停止自動旋轉的控制。

## 2. 實作

- 預設交付一個 `index.html`：HTML、CSS、JavaScript 放入同一檔；以原生 JavaScript 為主，不使用 React、Vue 或外部 JavaScript 框架。視使用者規定可用 Tailwind CDN；若要求離線，CSS 和必要素材須一併內嵌，不依賴 CDN。外部圖片、音訊如可合理嵌入則使用 data URI；評估體積與記憶體，不可能時說明限制並與使用者協調。
- 全景使用原生 WebGL 等可用技術建立可拖曳球面視角；注意紋理方向、無接縫、裝置紋理尺寸上限與 GPU 相容性。不因圖片看似寬幅而假設是球形全景。WebGL 不支援或載入失敗時提供可操作的平面備援，並標示備援視角的限制。
- 採清楚視覺主區、場景切換、任務入口、進度與適當的卡片、燈箱或手風琴。CSS media query 適配桌機、iPad 與 Android 平板；讓按鈕觸控面積足夠、狀態可辨、文字可讀。支援鍵盤、焦點管理、語意標籤、關閉對話框及 reduced-motion。
- 沉浸模式收起非必要工具列，保留場景、任務入口、離開與音樂控制；支援 Escape，必要時搭配 Fullscreen API，拒絕或不支援時仍可正常使用。以 `style.display` 控制互斥畫面可見性並確保恢復狀態，避免 CSS 權重衝突。
- 設計背景音樂預設關閉，需使用者點擊才啟動，並提供可見的播放／暫停狀態、播放失敗回饋、循環與獨立音效開關。若沒有取得音樂則不捏造已加入的素材。
- 以正確狀態管理任務完成：只有實際完成操作才計入，返回場景不誤重置；是否保存進度依需求說明。預設不收集個人資料、不加入追蹤或伺服器功能。

## 3. 驗證及交付

- 執行程式語法或靜態檢查；在環境允許時以瀏覽器檢查電腦與平板尺寸、場景切換、滑鼠與觸控拖曳、鍵盤操作、每個任務完成條件、進度、沉浸模式進出、音樂與音效、素材載入及 WebGL 備援。調整後重測受影響處。
- 明確區分「程式檢查通過」與「已在真實瀏覽器或設備操作確認」；若無法試聽或無設備實測，不聲稱已驗證。說明網路、檔案大小、瀏覽器或素材限制。
- 交付可開啟的 HTML 或可訪問網站、使用步驟、教學任務與實際測試結果。利用現有環境支援的持久化機制保存使用者要求的成果。

## 4. GitHub Pages 部署（僅使用者要求時）

- 先確認可用的 GitHub 連線、帳號、目標儲存庫及預期可見性。使用者指定沿用的儲存庫應檢視既有程式與部署設定，保護未相關的檔案與變更；不得預設覆蓋其他網站。若目標、帳號或公開範圍有實質歧義，先完成可審閱成果再詢問。公開發布會使網站內容與嵌入素材可被公眾存取；只有先前對同一發布動作的清楚授權可以沿用，不能推定所有未來網站皆公開。
- 先用可用的 GitHub 連線或 `gh`/git 驗證權限，準備檔案、檢查敏感資訊和授權。靜態網站須包含正確入口 `index.html`；採相對路徑處理專案網站的 `/<repo>/` 基底。不要提交金鑰、認證或學生個資。大檔案、GitHub Pages 可用性及儲存庫方案限制應依當前設定查證。
- 若是新網站且使用者已授權，建立合適的儲存庫並提交檔案；若更新既有網站，先檢查分支與狀態，再以非破壞方式更新。設定 GitHub Pages 的實際來源（分支／資料夾或 Actions）；若平台操作失敗，回報確切阻礙及後續步驟，避免聲稱部署成功。
- 等候發布並查詢部署狀態，開啟實際產生的網址檢查頁面、資源與關鍵互動。報告實際儲存庫、網站網址、公開性、驗證情形與未驗證項目；依環境能力說明操作中需要使用者登入或授權的具體步驟。不要暴露 token 或其他機密。
